# PL/SQL routines in Java

StarDataParadise Server 0.4.0 exposes read-only routine snapshots through wire v1.
A snapshot identifies the catalog object and immutable schema revision, includes
its dependency closure and reports hosted SQL and write effects. Creating a
standalone snapshot requires routine execution and DDL privileges. Connected
snapshots require execution permission and authorized dependency metadata. Files
are generated by the client in a new local directory.

## Standalone

Use Python 3.12 and an account with the required privileges.

```powershell
python tools/routine_export/snapshot.py --host localhost --port 7443 --ca ca.pem --user local-admin --routine export_position --mode standalone --output position.json
python tools/routine_export/emit_java.py --snapshot position.json --output position-java
gradle -p position-java build
```

The generated project compiles on JDK 17. Its entry point is
`stardataparadise.exported.Routines.invoke`. The output contains the routine
version, source locations, typed runtime and a digest manifest. Pure routines
support the bounded IR control flow, recursion, SQL NULL, exact decimal coercion,
checked BIGINT arithmetic and compound types. Hosted SQL and cursor instructions
are declined with their source positions. Trigger entry points are implicit.

The example fixture scores chess material and a position bonus and runs a
separate bounded two-branch search. It has no legal move generator.

## Connected

Fetch a snapshot with `--mode connected` and call
`tools/routine_export/emit_connected.py --snapshot FILE --output DIRECTORY --sdk-sha256 SHA256`
using the SHA-256 of the JDBC 0.2.0 JAR. The generated Gradle project requires
the two artifact paths through `-PsdpSdkJar` and `-PsdpGsonJar`; it verifies
both digests. JDK 17 compiles the wrapper. Pass an `SdpConnection` with
autocommit disabled to `ConnectedRoutine.invoke`, followed by the IN and IN OUT
values. The wrapper checks the exact catalog revision closure in its caller's
transaction, uses JDBC parameters for the call and returns ordered result sets.
Commit or roll back that transaction in the application.

The Server executes the connected routine and every hosted SQL operation. The
manifest records its revision and dependency revisions. Snapshots are
operational artifacts and standalone snapshots include routine logic.

The tests under `tests/routine_export` run Server oracles over real TLS, then
shut down the standalone Server before running Java. The connected test uses
the exact packaged JDBC driver, verifies permissions and rejects a changed
routine version.
