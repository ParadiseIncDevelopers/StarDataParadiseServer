# SQL compatibility

Etap 11 provides a SQL compiler and transactional catalog. The compiler tokenizes one UTF-8 statement, parses it into an AST, resolves identifiers and parameters, and emits a typed logical plan. The grammar is [SQL.ebnf](sql/SQL.ebnf). Source lines and columns are 1-based.

| Supported | Behavior |
| --- | --- |
| CREATE and DROP DATABASE, SCHEMA and TABLE | Catalog edits share the caller's transaction and durable WAL change set. The caller commits explicitly. Empty user namespaces can be dropped. The built-in `main.public` namespace is protected. |
| ALTER TABLE ADD COLUMN | Appends a column and advances the table schema version. Existing column ordinals remain stable. |
| SELECT, projection and WHERE | Compiles a single table or constant expressions, one table alias, comparisons, NULL predicates and three-valued boolean logic. |
| Named parameters | `:name` resolves against separately supplied parameter types. A bare column of the same name resolves against table columns. |
| Metadata | Objects have stable IDs. The catalog supports database, schema, table, index, view and routine descriptors. SQL creation of indexes, views and routines follows in later stages. |

A table name resolves relative to `main.public` when unqualified. With two components it uses `main.schema.table`. A table alias becomes the only visible table qualifier. Unquoted names fold ASCII letters to lowercase. Quoted names preserve UTF-8 bytes and use doubled quotes to escape a quote. JOIN and trigger creation return an unsupported diagnostic.

| Type | Rules |
| --- | --- |
| BIGINT, INTEGER, INT | Signed 64-bit integers with checked overflow. |
| DECIMAL(p,s) | Exact coefficient and scale. Precision 1–38 and scale no greater than precision. Ties round away from zero. Overflow is rejected after rounding. |
| BOOLEAN and NULL | Three-valued logic. WHERE selects only TRUE. |
| TEXT and BLOB | Valid UTF-8 text and separate binary values. Text comparison uses UTF-8 byte order. |
| DATE and TIME | Gregorian years 0001–9999. TIME permits up to nine fractional digits and excludes leap seconds. |
| TIMESTAMP WITH TIME ZONE | Explicit Z or signed offset up to ±14:00. Comparison uses the UTC instant. |

Local maintenance commands take the data-directory lock and inspect committed storage and WAL using read-only handles.

```powershell
.\StarDataParadiseServer.exe --config .\server.json --catalog-info
.\StarDataParadiseServer.exe --config .\server.json --check-sql .\statement.sql
```

`--catalog-info` emits JSON object IDs, qualified names, schema versions and ordered column definitions. `--check-sql` parses and binds a UTF-8 file and reports compatibility and inferred projection types. The internal checker accepts explicit parameter types. Etap 12 executes this SQL through the sql_crud_v1 extension when storage is initialized. It also supports INSERT VALUES, UPDATE and DELETE with typed named parameters and bounded fetch. See [SQL CRUD wire contract](contracts/sql/SQL_RPC_V1.md).

## Relational DDL and integrity

Etap 13 adds CREATE INDEX and CREATE UNIQUE INDEX on one or more named columns. B+ trees keep a stable root and order typed keys with the stable heap row ID as a tie breaker. Equality and range scans on a single indexed column apply the original predicate to each candidate. Text index ordering is binary in this etap. ALTER INDEX RENAME TO keeps the object ID and tree. DROP INDEX removes the tree and keeps the table rows.

CREATE TABLE accepts PRIMARY KEY, UNIQUE, FOREIGN KEY, CHECK, column DEFAULT and BIGINT GENERATED BY DEFAULT AS IDENTITY. Primary keys reject NULL. A unique composite key with any NULL component can repeat. A foreign key with any NULL component requires no parent. FOREIGN KEY references a primary or unique key with matching types. NO ACTION and RESTRICT are immediate. CHECK rejects FALSE and accepts UNKNOWN. Child rows must be changed before the referenced key can be changed or removed. Deferred constraints and cascading actions are unsupported.

CREATE and DROP SEQUENCE are transactional. DEFAULT NEXT VALUE FOR obtains a value when INSERT omits the column. An omitted identity column obtains its own counter value. An explicit identity value does not advance the counter. Rolling back a statement or a transaction restores sequence and identity counters with the affected rows.

CREATE VIEW accepts a named projection or wildcard from one base table. Views are read-only. The catalog keeps the original projected ordinals fixed even if a column is added to the table. Views, foreign keys and sequence defaults keep their referenced objects from being dropped until the dependencies are removed.

TRUNCATE TABLE and DROP TABLE use the same writer as row-level mutations and preserve prior row images in the WAL. Large DDL operations share the transaction's existing row, page and change-set limits. Catalog metadata includes object IDs, definitions and dependencies. The offline `--check-storage` command checks index and foreign-key consistency through read-only handles.

## Advanced SELECT and maintenance

Etap 14 adds INNER, LEFT and CROSS joins, GROUP BY, HAVING, COUNT, SUM, AVG, MIN, MAX, DISTINCT, UNION and UNION ALL, uncorrelated scalar subqueries and EXISTS, and nonrecursive CTEs. ORDER BY supports ASC, DESC and optional COLLATE. SUM and AVG return exact decimal values. The planner uses an equijoin hash path where supported and a nested loop for other join predicates. The plan accounts for ANALYZE row estimates at the matching table schema version and applies eligible filters before a join.

EXPLAIN returns the operator plan without executing the query. EXPLAIN ANALYZE executes SELECT and reports the result row count and wall-clock microseconds. The plan omits SQL text and parameter values. Advanced operators have a 4 MiB working budget per query. In the Server, an advanced result above 64 KiB is stored in the configured temporary directory with a 768 KiB per-result cap. Finishing or cancelling the result closes and removes the temporary file.

CREATE INDEX and REINDEX accept binary or Turkish collation. Turkish ordering uses Windows NLS and stores its sort version alongside the index. A stale index rejects mutations until REINDEX builds a replacement with current ordering metadata. REINDEX keeps the object ID and advances its metadata version. Binary comparisons keep their existing semantics.
